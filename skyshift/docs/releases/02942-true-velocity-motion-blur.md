## Implementation A–F
- A: Attach separate nearest-filter unsigned integer DepthTextures to both existing HDR composer targets. No second scene/depth render; shader samples the actual beauty readBuffer immediately after RenderPass, before UnrealBloomPass and SMAA. Resize through existing composer lifecycle; history invalidated on resize/reset/idle, long stalls, large camera translation/rotation cuts.
- B: Unproject current depth into view space and reproject via previous camera view * current camera world, with current projection at both ends to avoid artificial FOV-only blur. Previous transform recorded once per normal presentation update; actual camera direction/translation/rotation determine motion. No fixed radial origin, no color history, no per-object vectors.
- C: Zero gain at/below reference launch speed 44m/s, even with boost signal. Smooth speed gate 1–3.15× start speed, distinct shutter gain and max screen-height span for six modes. Actual physical speed already includes boost; at most 12% additional shutter gain. Normalize to 60Hz reference elapsed presentation interval, clamp long span; adaptive levels reduce gain, span and taps. Existing user mode preference retained, no automatic Extreme promotion.
- D: Symmetric depth-aware weighted 7/5/3-tap gather, reject out-of-screen and discontinuous depths; no luminance filter. Cost is more depth reads and two sampleable depth attachments; physical GPU time and thermals unverified.
- E: Conservative projected ship radius using camera depth/FOV, protects output and sample region; not exact object-ID masking, cannot fully handle transparency/animated objects or disocclusions. No fixed wide center road mask. Before bloom so bloom reflects moving scene, slight post-bloom spill into guarded region possible. Fullscreen, physics, ship, camera, bloom settings unchanged.
- F: Unit speed/idle/cut/quality/shader checks, explicit route checks, extended real Chrome WebGL proof on actual game with two consecutive actual physical/camera steps, same-scene A/B using recorded prior camera matrix, launch and stationary control, pre-bloom craft-core and nonbright-pixel checks, same drawcall/triangle counts apart from one fullscreen triangle, bloom 65% independent. Actual motion sequences/screenshots from renderer, not generated. No claim of physical mobile GPU speed or exact artistic quality before player test.
