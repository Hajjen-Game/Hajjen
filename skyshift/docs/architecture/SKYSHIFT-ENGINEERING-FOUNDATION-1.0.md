# SKYSHIFT — Engineering Foundation 1.0
**Binding engineering roadmap / source of truth.** Approved direction: 2026-11-24. Repository: Hajjen-Game/Hajjen. Scope: architecture, code quality, runtime, performance, reliability and development infrastructure; no gameplay redesign in this program.

## 0. Continuity and decision authority
Read this document FIRST in every new SKYSHIFT development session (including scheduled CI work), then [root consolidation status](SKYSHIFT-ROOT-CONSOLIDATION-STATUS.md), current main, open PRs and required checks. This document supersedes the older file-count-first roadmap wherever they conflict. Historical migration records remain evidence, not new design requirements. Do not silently change scope, sequence, acceptance criteria or architectural principles. Only the user can approve a change of direction; record it here with date, rationale, implications and migration plan. Implementation details may evolve based on measured evidence, without changing the approved objectives. If a stage is blocked, document the blocker and propose a bounded alternative; never mark it complete without evidence.
Do not create parallel conflicting PRs; finish or reconcile existing work first. Update the current stage and next action here as part of each substantive PR, with actual merged commit, tests, measurements, and remaining risks. Use Git history/tags as rollback archive. Green CI alone is not proof of architectural completion. Prefer coherent batches (~30–80 files where safe), not arbitrary tiny migrations; functional risk, not file count, determines boundaries.

## 1. Owner decisions: Vault-first, generic engine
- Neon Vault Circuit is the primary development track and approved visual reference (current 0.28.9.7 appearance). Preserve it as the comparison baseline. It is not the owner of general engine or material code.
- Skyline Circuit and Aurora Run are frozen: no independent art, layout or gameplay development. They are temporary compatibility/feature fixtures until generic capabilities, dependencies and relevant regression coverage are secured; then retire their playable catalog entries and obsolete track-specific code/assets in an explicit, verified migration. Do not remove them prematurely or keep them permanently just for source snapshots. Preserve recoverability via Git.
- Retain existing reusable flight and geometry capabilities even if Vault does not currently use them: ramps, jumps/gaps, elevation/grade, banked curves, airborne control, air tricks, landing and landing boosts, GRIP, boosts, camera and motion/VFX; retain wall-ride and corkscrew support until an explicit owner decision says otherwise. These are future capabilities, NOT dead code. Preserve physical behavior and controls. Introduce jumps into Vault in a later gameplay task, not during this engineering program. Use small generic synthetic test tracks/fixtures for features not yet present in Vault; prove parity against existing Skyline before retirement.
- The approved Vault tunnel appearance is the single default shared tunnel style. Every track using that style automatically receives improvements to geometry, material, shader, neon fixtures, zone wave, road/rail/ship light response and reflections. No per-track copies or version-gated forks of the same style. Tracks supply only authored centerline, frame/pose, length, tunnel intervals, banking, elevation, gaps and permitted data-driven placement parameters. Future distinct themes require an explicit owner decision and reuse the shared engine.
- While Skyline is still playable, transition its tunnel to the same approved shared style, not a separately maintained renderer; Aurora currently has no tunnel, so do not add one merely for parity. Keep track layouts and physics unchanged in this program. Confirm with at least two different track samplers/fixtures, including curved/banked/elevated sections and tunnel boundaries. Visual parity means same design/material behavior, not identical screenshots of different geometry.
- Modern mobile (iPhone 16) and representative desktop are primary targets; older A51/4GB-class is compatibility/fallback, not the primary visual design target. Do not reduce approved graphics just to optimize an old device. Distinguish measured real hardware from emulated/software WebGL.

## 2. Non-negotiable engineering principles
One current implementation per responsibility; version history in Git, not production filenames, chained classic flags or permanent copies. Explicit interfaces and one-way dependencies; physics is renderer-independent; track data independent from global browser URL state; tunnel accepts track sampling contracts, not a track name; avoid string-named scene objects as inter-system APIs. No needless frameworks, ECS, engine rewrite, dependency or abstraction. Keep Three.js, fixed-step 120Hz simulation/interpolation, adaptive render quality, nonblocking GPU metrics, analytical track math and valid resource-sharing optimizations unless measured evidence and a documented decision justify a change. Prefer simple stable names, central typed contracts (gradual TS/checkJs, not a mass rewrite), central build version, explicit resource ownership/disposal, minimal allocations and work in frame loops. No changes to physics/controls/gameplay or deliberate loss of Vault visuals without separate approval. No blanket deletion by filename or static scan alone; verify dynamic imports, URLs, shaders, assets, tests and workflows. Production and QA use the same engine; QA-only hooks and historical A/B comparisons must not ship in default runtime. Preserve functional regression coverage; retire temporary migration assertions only when their protection is superseded, never just to turn CI green.

## 3. Ordered stages and gates
EF01 — Runtime & Performance Baseline (IN PROGRESS). Pin approved Vault 0.28.9.7 and current main commit; capture full live/QA/comparison dependency graphs, dynamic URL references, reachable/unreachable source counts and bytes, duplication families, active paths per track, actual CSS/assets/shader dependencies. Measure cold/warm boot, network transfer, scene construction, shader compile, PMREM, first playable frame, CPU/GPU p50/p95/p99, draw calls, triangles, renderer resources and memory/repeated run stability. Save reproducible screenshots at fixed poses/quality, physics/trick/GRIP/boost fixtures, and documented devices/browser/build. Use existing CI/browser probes, real-device data where available; report missing metrics explicitly. No guessed gains. Exit: durable baseline and prioritized evidence-backed inventory, with rollback reference; review L1H inventory rather than restart mechanical file moves.

EF02 — Dead Code & Dependency Elimination. Classify live/default, other supported runtime, QA/fixture, and historical-only. Retire confirmed obsolete snapshots and duplicated implementations with coherent consumers; preserve unique engine capabilities (section 1) and rollback. Relocate remaining active root modules into clear ownership, stable names when safe, target <=10 intentional root files but no file-count-only optimization. Replace near-identical variants by shared implementations/explicit inputs. Freeze Skyline/Aurora; identify retirement dependencies, do not remove them until EF04/EF05 gates are satisfied. Exit: measured graph/bytes/duplicate reduction, no broken imports/assets, coverage of existing behavior, intentional root exceptions documented.

EF03 — Modern Build Pipeline. Introduce minimal Vite/npm build (pin Three.js and lockfile; retain GitHub Pages and existing URLs/explicit migration for them), content-hashed minified build, tree shaking, lazy track/QA modules, single version source, consolidated current CSS preserving cascade and visuals. Separate production and dev/QA entrypoints, ensure test code not included in production bundle. No extra framework. Exit: reproducible install/build, actual published bundle and cache checks, current rendering/controls unchanged, measured startup/transfer and no broken Pages links. Validate tool versions at implementation time.

EF04 — Core Engine Decomposition. Split game-v0210.mjs into orchestration/lifecycle, simulation, track sampling, input, camera, vehicle/effects, UI, persistence and diagnostics. Keep a fixed simulation clock and interpolation; explicit state/API contracts, no unnecessary event buses. Extract reusable Skyline/Aurora flight/geometric capabilities into track-independent engine modules; add synthetic fixtures for jumps, air tricks, landing boosts, banking/elevation, gaps, wall ride/corkscrew, GRIP/camera. Exit: generic features verified independent of legacy playable tracks; reduced central coupling and QA hooks; behavior parity and existing regression checks.

EF05 — Unified Environment & Material Engine. Vault is approved visual baseline; consolidate the historic installer/shader chain into one shared default tunnel renderer driven by generic track sampling/config. Remove track-name hacks, fake road material dependencies, chained historical release gates, hidden obsolete overlays (avoid allocating them in first place), unnecessary passes and shader wrappers when parity proven. Explicit references for geometry/material/light ownership; shared source data drives road/rail/ship/wall light and zone wave; retain straight-only edge sources, white core and interior lighting, approved reflections and continuity. Test on Vault, Skyline while retained, and independent synthetic curved/banked/elevated sections; same shared style, no per-track implementation. Confirm no visual regressions on High and 4GB profiles; compare real WebGL captures, not only metadata. After EF04/EF05 gates and verified dependency/feature inventory, retire Skyline/Aurora from playable catalog and remove exclusive obsolete code/resources; preserve necessary tests with generic fixtures and Git rollback. Exit: one default tunnel pipeline, demonstrated change propagation, no required feature lost; retirement explicitly logged.

EF06 — Resource Management & Startup. Explicit renderer/scene/track/vehicle lifetimes; asset cache, leases/refcounts, shader warmup, lazy loading selected track, chunk geometry where warranted, cancel/teardown RAF/listeners/render targets/materials/textures safely; handle WebGL context loss/recovery; evaluate in-page track switching rather than reload if warranted for future tracks. Avoid hitching or reducing visual quality. Exit: repeatable load/unload/track-switch or reload lifecycle, no observed unbounded resource growth, startup measured against baseline.

EF07 — Measured Performance Optimization. Profile real CPU/GPU/memory hot spots; benchmark batching/instancing, spatial culling, LOD, shader variants, overdraw, pass consolidation, allocation reuse, track sampling, idle work and adaptive settings independently. Keep only measured beneficial changes; preserve visuals and physics. Target smooth 60 FPS (16.67 ms frame interval) on primary mobile/desktop profiles where feasible, 120 FPS (8.33 ms) stretch target; measure frame pacing and p95/p99, not average alone. No promised target on unmeasured hardware. Exit: before/after evidence per change and no unacceptable regression, with limitations documented.

EF08 — CI & Regression Simplification. Consolidate redundant path/SHA/count/archived-source checks after migration; retain active unit, integration, browser, visual, performance and dependency-boundary gates. Test current engine not frozen implementation details. Keep genuine WebGL/Pages and 120Hz/flight feature regressions. Use deterministic inputs, shared test harness and change-aware CI without skipping necessary tests. Exit: faster measured CI and maintained functional coverage, clear final acceptance report, clean ownership and future-track demonstration.

## 4. Delivery / acceptance protocol for every stage
Before edit: read this plan/status; inspect current main SHA, open PRs, checks; capture scope, affected dependency graph and rollback; verify stage prerequisites. During edit: one coherent PR, explicit scope, no unrelated gameplay/visual changes, no skipped required tests; document proposed architectural decisions. Before merge: current required PR checks green, appropriate actual behavior/visual tests, no unexplained regression; do not merge conflicts or stale head. After merge: verify actual main and relevant Pages/track workflows, measure objective results and update status/next step. If a check fails, diagnose and fix or rollback rather than bypass it. Distinguish checked evidence, hypotheses, and unavailable measurements. A documented owner-approved scope change is the only exception to the roadmap; do not silently substitute a different strategy.
