# 0.29.8 — Instant Boot & Race Loading

Explicit Vault 0.29.8 inherits 0.29.7 speed profile, jump, rail color hold, graphics and ship. The legacy 0.29.7 URL remains eager; 0.29.8 with instantBoot=classic is the same-release eager comparison. No changes to authoritative physics or renderer quality. Main merge gated by CI and approval.

The bootstrap loads only the lightweight DOM menu and storage APIs first, never the game module until START RUN. Settings, fleet unlock/selection and validated Hyper personal best are available before WebGL. A single import promise and captured fullscreen gesture prevent duplicate loads. Before game ownership is transferred the menu listeners are removed. A six-step progress bar counts real milestones, not fabricated percent or time. Double RAF yields allow the loading overlay to paint before heavy module import and between road/tunnel/reflection build phases; compileAsync and one actual composer warm frame precede race start. The race starts only after successful initialization. Existing pause/retry/menu resource lifecycle reuses the loaded renderer. Failures reveal retry; no silent dead menu. No speculative prefetch of the heavy runtime.

Cold hangar is text/card based for this release: equip/preview selection works without WebGL, the original live 3D hangar is restored once the first race environment is loaded. A fully independent live 3D showroom remains a future pass, not implemented here. No new countdown or simulated progress. Initial menu timing is measured in boot.menuReadyMs, load time in boot.raceLoadMs; mobile under 1s is a goal not a verified result. Physical S26 and actual browser paint/thermal evaluation remain necessary. Built Chrome proof exercises pre-race settings and hangar without loading the engine, START loading milestones, warm frame, menu return and existing full graphics/fidelity/physics proofs.
